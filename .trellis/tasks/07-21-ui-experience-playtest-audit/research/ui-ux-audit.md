# 《百戏奇牌》UI 与玩家体验试玩审计

> 状态：试玩与跨浏览器复核已完成
> 审计日期：2026-07-21（Asia/Shanghai）
> 审计范围：中文版桌面端 UI、交互反馈与体验；不评价或修改玩法、平衡、经济、难度与内容池

## 1. 总体结论

《百戏奇牌》的视觉身份已经成立：午夜戏台、纸张、朱砂与金色在菜单、牌桌、夜市和大图鉴赏中保持一致；选牌抬起、计分脉冲、自动排序、目标选择与奇牌大图都能清楚传达状态。两档官方桌面视口未发现页面级溢出、关键按钮相互遮挡或必须滚动才能完成的核心操作。

本轮完成了首次玩家八步教程、回流玩家普通局、资料/维护页面、成功/拒绝反馈、音频与演出速度控制，以及普通局失败终局。最终记录 **1 项 P0、1 项 P1、7 项 P2、1 项 P3**。最高优先问题不是美术，而是教程第 7 步的恢复性：玩家能买入不兼容补充包，随后“选此件”和“放弃余项”都被拒绝，当前教程无法继续。该问题已在 Chromium 与 WebKit、1280×720 与 1920×1080 复核，不是单一浏览器现象。

推荐先修：

1. 教程补充包防错与恢复路径（UX-001）。
2. 将牌桌排序、选牌状态、出牌/弃牌收进同一手牌操作轨（UX-002）。
3. 使用教程专用谢幕信息，移除互相矛盾的普通局指标（UX-003）。
4. 为稀疏夜市货架设置卡片最大尺寸和居中网格（UX-004）。
5. 让大舞台面板按内容构图，而不是在 1920×1080 被动拉满（UX-006）。

### 评价镜头

- 焦点与层级：最重要的信息、对象和下一步行动是否显眼。
- 可发现性：第一次看到页面时，玩家能否推断哪些元素可操作、为什么可操作。
- 可读性与密度：中文文案、数字、牌面与奇牌图像能否在正常缩放下快速扫读。
- 空间一致性：同类控制是否保持稳定位置和明确归属。
- 反馈与恢复：接受、拒绝、等待、完成、取消和返回是否都有清晰反馈。
- 动效与声音：反馈是否帮助理解状态与节奏，是否遮挡控制或制造无意义等待。
- 重复效率：回流玩家是否承担不必要的点击、等待、指针移动或上下文切换。

### 严重度

| 等级 | 定义 |
|---|---|
| P0 | 官方基准视口上的必要路径无法发现或无法完成 |
| P1 | 常用或关键路径上造成重大误解、犹豫或重复摩擦 |
| P2 | 明确且可复现的局部/重复摩擦 |
| P3 | 有潜在收益、但需要验证的润色或视觉实验 |

## 4. 值得保留的体验

- 档案创建弹层目标单一，首次提示把“开始教程”和“暂时跳过”区分得很清楚。
- 手牌选中后抬起并描边，计分圆心有集中反馈，出牌后的自动排序即时生效。
- 奇牌鉴赏是本轮最成熟的素材利用方式：大图不裁切，名称、稀有度、效果、当前值和风味文案有稳定层级；可作为其他素材放大方案的参照。
- 52 张目标牌在 1280×720 内完整可见，选择态和确认按钮稳定，不需要外层滚动。
- 教程买入奇牌后自动从“单品”切到“补充包”，减少了一次解释和寻找。
- 声场抽屉的速度选中态、数值滑杆和“静音/恢复声场”文案明确；未再发现此前的控件遮挡。
- 图鉴筛选与搜索虽然密集但可用；维护页把危险操作放进明确的红色区域；计分演出节奏利落，没有阻塞下一步操作。

## 5. 优先发现

### UX-001 — 教程允许买入不兼容补充包，随后无恢复路径

| 字段 | 结论 |
|---|---|
| 严重度 / 类型 | **P0**；客观流程阻断、反馈与恢复缺陷 |
| 玩家 / 频率 | 首次玩家；教程第 7 步一次触发即可永久卡住当前教程 |
| 浏览器 / 视口 | Chromium 与 WebKit；1280×720 与 1920×1080 共享 |
| 路径 / 状态 | 新档案 → 八步教程 → 完成前 6 步 → “打开补充包” → 购买 `奇面小匣·一` → 奇牌候选 |
| 复现结果 | “选此件”被拒绝；“放弃余项”也被拒绝；WebKit 中两次操作前后检查点均为 `#22`，候选状态未清除；底部只重复教程目标 |
| 影响 | 玩家无法在当前教程内完成第 7 步，也不知道哪一种包才兼容；只能放弃/跳过教程或重建档案，首次信任直接受损 |
| 建议 | 在购买前给兼容包加“教程可用 / 产出消耗牌”印记；教程期间禁用不兼容购买并显示原因；即使已开错，也必须允许“放弃余项并返回夜市”，拒绝时明确说明原因与下一步 |
| 收益 / 代价 | 消除唯一实测硬阻断，同时教会玩家补充包品类；代价是教程期间减少自由试买，并需要复用包类型元数据与补充恢复测试 |
| 规模 / 风险 | **M**；中风险，涉及夜市按钮状态、教程守卫、选择页恢复和端到端用例 |

复现证据：[购买前无兼容标识](evidence/chromium-1280x720-tutorial-step7-shop-packs.png)、[Chromium 无法放弃](evidence/chromium-1280x720-tutorial-pack-abandon-rejected.png)、[WebKit 选择被拒绝](evidence/webkit-1280x720-tutorial-wrong-pack-rejected.png)、[WebKit 1920 无法放弃](evidence/webkit-1920x1080-tutorial-wrong-pack-abandon-rejected.png)。

标注证据：[购买前缺少防错](evidence/annotated-ux-001-pack-guidance.svg)、[选择与放弃同时失效](evidence/annotated-ux-001-no-recovery.svg)。

### UX-002 — 高频手牌操作被拆散在屏幕三端

| 字段 | 结论 |
|---|---|
| 严重度 / 类型 | **P1**；重复交互摩擦、控制归属不清 |
| 玩家 / 频率 | 首次与回流玩家；每次选牌、排序、出牌或弃牌都会遇到，回流玩家成本更高 |
| 浏览器 / 视口 | Chromium 与 WebKit；两个视口共享，1920×1080 最明显 |
| 路径 / 状态 | 任意牌桌回合，至少选中 1 张手牌 |
| 复现结果 | 手牌位于底部中央；“按点数/按花色”固定在最左下；“出牌/弃牌”固定在最右下；一次决策的相关控件没有共同容器 |
| 影响 | 宽屏上反复横跨，降低操作节奏；新玩家也更难把排序、选择计数和提交动作理解成同一个手牌工作流 |
| 建议 | 建立底部“手牌操作轨”：排序靠近手牌左侧，已选数量/预计牌型居中，出牌/弃牌靠近手牌右侧；保留纸牌倾斜和戏台构图，不改变牌桌规则 |
| 收益 / 代价 | 减少指针移动并强化控制归属；代价是需要重排底部安全区并复核牌扇、演出、提示条和两个视口的碰撞 |
| 规模 / 风险 | **M**；中风险，主要是响应式布局、命中区与动效锚点 |

证据：[Chromium 1920 选牌态](evidence/chromium-1920x1080-ordinary-table-selected.png)、[WebKit 1280 选牌态](evidence/webkit-1280x720-tutorial-table-selected.png)、[WebKit 1920 选牌态](evidence/webkit-1920x1080-tutorial-table-selected.png)。

### UX-003 — 教程谢幕套用普通局指标，信息互相矛盾

| 字段 | 结论 |
|---|---|
| 严重度 / 类型 | **P2**；客观呈现矛盾、完成感受受损 |
| 玩家 / 频率 | 首次玩家；教程结束一次 |
| 浏览器 / 视口 | Chromium 1280×720 已确认 |
| 路径 / 状态 | 完成 8/8 教程后进入胜利谢幕 |
| 复现结果 | “最终得分 0 / 目标 0 / 剩余出牌 0”与“最后一手 两对 +116”同时出现；“本局永久进度”标题下方又说明教程不改变永久进度 |
| 影响 | 玩家难以判断自己做对了什么，也会怀疑分数、目标或存档是否失效；削弱八步完成后的奖励感 |
| 建议 | 使用教程专用谢幕：突出 `8/8`、已掌握的四组动作与“教程不写入普通局进度”；隐藏无意义的普通局 0 值指标，可保留最后一手作为学习回顾 |
| 收益 / 代价 | 提升完成感与口径可信度；代价是结果页需要一个轻量教程变体 |
| 规模 / 风险 | **S–M**；低风险，注意不要影响普通局胜负结算 |

证据：[教程完成页](evidence/chromium-1280x720-tutorial-complete.png)。

### UX-004 — 稀疏夜市货架把少量内容拉成巨大空卡

| 字段 | 结论 |
|---|---|
| 严重度 / 类型 | **P2**；视觉层级与素材利用不足 |
| 玩家 / 频率 | 回流玩家；每次夜市商品较少时重复出现 |
| 浏览器 / 视口 | Chromium 1920×1080 已确认 |
| 路径 / 状态 | 普通局领奖进入夜市，单品页仅有两件消耗牌 |
| 复现结果 | 两张商品卡横向拉满货架，正文与印章仍很小，大量纸面空白；价格按钮远离标题和效果，右侧持有物面板也显得空 |
| 影响 | 高质量素材没有成为识别锚点，扫读顺序被空白打断，页面看起来像未完成的占位布局 |
| 建议 | 给商品卡设置最大宽高，1–2 件居中、3–4 件扩展为紧凑网格；放大品类图形/素材，稳定“素材 → 品类 → 效果 → 价格”的层级 |
| 收益 / 代价 | 提高素材可见度与商品比较效率；代价是需要验证不同商品数量、长文案和两个官方视口 |
| 规模 / 风险 | **M**；中风险，依赖现有商品卡与货架响应式规则 |

证据：[普通夜市两件商品](evidence/chromium-1920x1080-ordinary-shop.png)。

### UX-005 — 奖励阶段仍显示上一阶段的教程指令

| 字段 | 结论 |
|---|---|
| 严重度 / 类型 | **P2**；局部状态文案滞后 |
| 玩家 / 频率 | 首次玩家；教程击败盲注后一次 |
| 浏览器 / 视口 | Chromium 1280×720 已确认 |
| 路径 / 状态 | 教程达标进入“赏银收据” |

| 收益 / 代价 | 低成本消除一次关键转场疑惑；需要补充 phase 文案映射测试 |
| 规模 / 风险 | **S**；低风险 |

### UX-006 — 1920×1080 的大舞台面板被动拉满，形成重复死区

| 字段 | 结论 |
|---|---|
| 严重度 / 类型 | **P2**；跨页面构图与视觉节奏问题 |
| 玩家 / 频率 | 首次与回流玩家；菜单、设置、盲注、维护、公告等多页重复 |
| 浏览器 / 视口 | Chromium 1920×1080 已确认 |
| 路径 / 状态 | 回流菜单、普通局设置、维护、公告空状态、盲注选择 |
| 复现结果 | 核心内容集中在上半区，但深色容器延伸到接近底部；背景戏台被大面积盖住，呼吸感变成无意图的空洞 |
| 影响 | 信息显得稀薄，主次关系变弱；不同页面虽有内容差异，却呈现相同的“上挤下空”节奏 |
| 建议 | 按页面选择内容高度容器，或把下半区设计成明确的舞台脚注、状态/预览与装饰区；不要求填满每个像素，但空白必须有构图意图 |
| 收益 / 代价 | 提高大屏完成度并让背景素材重新参与构图；代价是需要逐页面而非全局粗暴缩高 |
| 规模 / 风险 | **M–L**；中风险，涉及共享舞台壳与页面级例外 |

证据：[回流菜单](evidence/chromium-1920x1080-menu-returning.png)、[普通局设置](evidence/chromium-1920x1080-campaign-setup.png)、[维护](evidence/chromium-1920x1080-maintenance.png)、[公告空状态](evidence/chromium-1920x1080-notices-empty.png)、[盲注选择](evidence/chromium-1920x1080-ordinary-blind.png)。

### UX-007 — 成就页向玩家暴露 31 个内部标识

| 字段 | 结论 |
|---|---|
| 严重度 / 类型 | **P2**；沉浸与扫读噪声 |
| 玩家 / 频率 | 回流玩家；每次浏览成就页 |
| 浏览器 / 视口 | Chromium 与 WebKit，1920×1080 共享；WebKit 页面计数 31 个 `bxqp:achievement:*` |
| 路径 / 状态 | 主菜单 → 百戏成就簿 |
| 复现结果 | 每张成就卡都显示类似 `bxqp:achievement:001` 的内部 ID，与标题、条件和进度竞争 |
| 影响 | 破坏戏台语境，也让玩家误以为这串代码具有操作意义 |
| 建议 | 玩家模式隐藏内部 ID；需要排查时放进开发模式、复制详情或元素标题，不占主界面层级 |
| 收益 / 代价 | 立即降低噪声；调试人员少一个常驻可视字段 |
| 规模 / 风险 | **S**；低风险 |

证据：[Chromium 成就页](evidence/chromium-1920x1080-achievements.png)、[WebKit 成就页](evidence/webkit-1920x1080-achievements.png)。

### UX-008 — 分享码复制反馈离触发按钮过远

| 字段 | 结论 |
|---|---|
| 严重度 / 类型 | **P2**；局部反馈不近因 |
| 玩家 / 频率 | 回流玩家；每次复制普通局分享码 |
| 浏览器 / 视口 | Chromium 1920×1080 已确认 |
| 路径 / 状态 | 普通战役设置 → 重取种子 → 复制分享码 |
| 复现结果 | “分享码已复制”出现在预览区下方，与按钮相距较远；视线停留在按钮时不易察觉 |
| 影响 | 玩家可能重复点击或怀疑剪贴板失败 |
| 建议 | 按钮短暂变为“已复制 ✓”，必要时保留现有全局提示作为冗余 |
| 收益 / 代价 | 即时确认、几乎无学习成本；需要处理短暂状态复位 |
| 规模 / 风险 | **S**；低风险 |

证据：[复制后的设置页](evidence/chromium-1920x1080-campaign-share-copied.png)。

### UX-009 — 两项补充包候选在 1280 宽屏左贴，右半区失衡

| 字段 | 结论 |
|---|---|
| 严重度 / 类型 | **P2**；局部构图与选择聚焦不足 |
| 玩家 / 频率 | 首次与回流玩家；补充包只有两项候选时 |
| 浏览器 / 视口 | Chromium 1280×720 已确认 |
| 路径 / 状态 | 教程买入不兼容补充包后进入两张奇牌候选 |
| 复现结果 | 两张大卡从左侧开始排列，右半屏留空；候选组没有视觉居中，放弃动作也容易落到首屏下缘 |
| 影响 | 选择焦点偏移，页面显得临时拼接；在 1280×720 下恢复动作的可见性进一步变差 |
| 建议 | 候选容器设置最大宽度并按数量居中；把“放弃余项”放进固定选择操作栏，而不是跟随卡片流 |
| 收益 / 代价 | 提高选择聚焦和恢复动作稳定性；需验证 1–5 项候选及长文本高度 |
| 规模 / 风险 | **S–M**；低到中风险 |

证据：[两项补充包候选](evidence/chromium-1280x720-tutorial-pack-joker-choice.png)。

### UX-010 — 牌型帮助可试验小型牌例，而非继续增加正文

| 字段 | 结论 |
|---|---|
| 严重度 / 类型 | **P3**；主观、需验证的视觉学习实验 |
| 玩家 / 频率 | 首次玩家与忘记牌型的回流玩家；按需访问 |
| 浏览器 / 视口 | Chromium 1920×1080 已观察 |
| 路径 / 状态 | 主菜单 → 牌型帮助 |

## 8. 建议的后续实施拆分

不在本审计中创建任务；如批准实施，建议拆成四个可独立验收的后续工作：

1. **教程韧性**：UX-001、UX-003、UX-005；验收重点是所有可购买包都能完成或安全退出教程，教程谢幕不再显示矛盾 0 值。
2. **牌桌操作轨**：UX-002；验收重点是两个官方视口无碰撞、选牌后自动排序保留、出牌/弃牌/排序命中区稳定。
3. **自适应卡片与舞台**：UX-004、UX-006、UX-009；验收重点是 1–5 项内容、长中文文案和 1280/1920 构图。
4. **低风险润色**：UX-007、UX-008，并把 UX-010 留作独立实验，避免与缺陷修复混批。
